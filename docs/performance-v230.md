# REBORN v230：减少游玩中的无效计算

本轮以 v229 的真实运行剖析为起点。保持画质档位、像素比策略、模型、材质、阴影、敌人数量、特效上限、伤害、移动和存档规则，不把降低画质当作优化成果。

## 实际修改

- `adventure-overheads.js`：合并后的森林岩壁横跨大范围，原来的整体包围盒无法排除许多相机射线。索引超过 1,024 个三角形的普通静态网格现在使用每片最多 256 个原三角形的 CPU 查询代理，先筛除远处片段，再交给现有精确射线检测。共享原顶点与索引存储，代理不进入场景，不增加渲染调用，不改变可见模型。保留最近命中、原网格、法线、相机退让距离和动态父级变换；顶点/索引更新时刷新；骨骼、形变、多材质、交错缓冲及不完整三角形范围回退原查询。
- `actor-collision.js`、`encounters.js`：对不可能接触的远邻先检查轴向距离，近处仍按原精确距离处理。扫掠移动算法保持原样；一个没有稳定收益的提前判断方案已撤回。
- `target-awareness.js`：每个敌人复用自己的最后观察位置，减少重复分配。潜行时保持最后位置，诱饵仍是独立目标，绝不引用隐藏玩家的实时坐标。
- `first-person-view.js`、`main.js`：主世界阴影完成后，绘制手臂与武器时跳过只含世界层内容的地图分支。仍使用同一场景、三盏原有灯光、环境反射和世界阴影；待更新或自动阴影时回退旧路径，异常也恢复全部状态。没有改动 Three.js、MSAA 或后期效果。

没有新下载模型、纹理、音效或依赖。所有新增工作都在 REBORN 中；NEXT 与原版未修改。

## 定向测量

以下为同机 CPU 微基准，**不是整局 FPS 或 GPU 帧时间**。

| 路径与工作量 | 原版中位 | 新版中位 |
| --- | ---: | ---: |
| 同一真实森林的 2,256 次屋顶/岩壁射线，9 轮交替顺序 | 102.745 ms | 12.881 ms |
| 60 怪分散分布，3,600 次分离计算，11 轮 | 3.684 ms | 0.877 ms |
| 60 怪密集分布，3,600 次分离计算，11 轮 | 4.094 ms | 1.535 ms |
| 分散角色，3,600 次落点净空检查，11 轮 | 9.427 ms | 4.749 ms |
| 60,000 次观察位置更新，11 轮 | 1.193 ms | 0.734 ms |

森林测量逐条对比 564 组射线，其中 64 组实际命中，位置、距离、法线与网格归属一致。第一人称使用仓库实际渲染器遍历和阴影代码的检查中，测试地图分支访问次数 2,503 → 0，装备、灯光与阴影引用一致；这不能直接推算为相同百分比的帧率提升。

原始记录在工作区 `outputs/performance-v230/overhead-benchmark.json` 与 `outputs/perf-sim230/benchmark-result.json`，包括被否决方案和逐轮耗时。

## 实战比较方法

旧版基线直接取自提交 `175e2fa9986c1dbd909864bdfe94dc5799a7af50` 的 Git 文件内容，不回滚工作区。冻结旧版 `229-5d2f079d5dca`，368 个文件逐项 SHA256 验证，53,625,836 字节。

使用同机 Edge、RTX 3080 Ti、固定地图种子 228144、高画质、岚歌长弓、正式准备流程及正常输入。保留自然刷怪、碰撞、伤害、音频、升级和闪避，没有无敌或禁止刷怪。桌面为 1280×720 / DPR 1，手机尺寸模拟为 844×390 / DPR 1.5。手机模拟仍使用电脑 GPU，不等于真机测试。

初始 60 秒诊断在约 46–53 秒自然死亡，完整保留为未完成样本。正式比较采用同角色和同路线的共同 45 秒窗口，不修改生命或敌人来延长测试；森林、合流、手机尺寸森林分别按旧→新→新→旧顺序测量。成长/奖励暂停间隔单独记账。开场截图及前 2 秒与稳定段分开，避免把截图开销计入稳定游玩卡顿。

最初森林剖析中，运行期没有新着色器编译；93 次小型垃圾回收总计约 51.51 ms，最长约 0.898 ms。某个 50.1 ms 显示间隔对应的前后 CPU 回调为 6.0 / 7.2 ms，其间约 37.8 ms 处于 CPU 空闲，未与垃圾回收或编译重叠。不能把所有长显示间隔都归因资源加载，也不能把 CPU 提交时间当作 GPU 执行时间。

### 实际结果

最终冻结构建为 `230-1ff9d4dabfb0`，368 项资源、53,629,370 字节，比旧版增加 3,534 字节，约 3.45 KiB。没有增加模型或贴图下载体积。

12 段交叉实战全部保留：11 段完成要求的 45 秒，一段新版森林在游戏时间 35.18 秒自然阵亡，实际观察壁钟 36.81 秒，列作部分窗口而非通过完整时长。没有挑选重跑来替换它。三种场景的四次运行均保持画质系数 1、相同目标缓冲，森林着色程序 499、合流 549，前后相同。

| 场景，两次运行合并 | 原版 | 新版 |
| --- | ---: | ---: |
| 合流平均渲染频率 | 59.02 FPS | 59.96 FPS |
| 合流游戏更新 P95 / P99 | 5.6 / 24.1 ms | 2.9 / 3.7 ms |
| 合流最慢游戏更新 | 88.6 ms | 6.5 ms |
| 合流超过 50 ms 的游戏更新 | 11 帧 | 0 帧 |
| 合流超过 50 ms 的渲染间隔 | 12 次 | 1 次 |
| 森林共同 34.80 秒窗口，游戏更新 P95 | 2.6 ms | 1.5 ms |
| 手机尺寸森林共同 43.30 秒窗口，游戏更新 P95 | 1.8 ms | 1.5 ms |
| 手机尺寸森林渲染频率 | 30.00 FPS | 30.00 FPS |

森林平均仍约 60 FPS；原版两次没有超过 50 ms 的稳定段间隔，新版第二次有一个 51.8 ms 间隔，因此不能说每种场景都消除了孤立停顿。手机尺寸的四次运行都没有超过 50 ms 的稳定段间隔，也不能据此承诺手机真机零卡顿。

同一输入计划和地图种子不等于逐帧战斗回放：帧调度、模型对象创建所消耗的全局随机序列、自然成长选择时机会影响敌人、发射数量与剩余生命。每次运行的这些数据都保留在原始报告，不能把整个自然实战的差值全部归因某一行代码；定向微基准另用完全相同输入验证计算收益。

旧版合流另做一次独立剖析，在游戏 14.7003 秒捕捉到 44.1 ms 游戏更新，其中移动调用栈累计约 41.79 ms，沿 `walkActor → moveActor → actorClearAt → canMoveBelowOverhead → firstHit → 三角求交` 集中。该慢帧与垃圾回收或着色编译不重叠，符合跳跃中多次查询整片岩壁的机制；没有把缺少剖析栈的原 95.8 ms 间隔逐个强行归因。

完整原始帧、调用栈、截图、失败/早死样本与逐段表在工作区 `outputs/performance-v230/`，正式 12 段的报告为 `ab/summary.md` 和 `ab/summary.json`。本轮测量没有并行打包或测试浏览器；剖析数据与正常 FPS 对照分开。

- 实际浏览器进行 12 种组合、48 个视角的旧绘制路径→新绘制路径→旧路径重复对照，覆盖森林树荫/营火、山谷/晶窟、两种武器、桌面/手机尺寸与视角往返。每组实际渲染、刷新阴影；调用数和三角面数均相同，页面异常及游戏请求失败为零。

即使定向计算显著减少，也不能保证所有手机、浏览器、后台负载和长时间战斗都绝对零停顿。本轮不声称缩短首次完整下载/加载，也不把手机屏幕模拟、单机短窗口替代真机发热测试或四台设备的公网混战。
