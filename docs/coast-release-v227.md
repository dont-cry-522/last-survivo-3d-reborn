# v227：海港远岸、正式游玩性能复核与离线交付

本轮以完整冻结的 v226 脏工作区为基线，仅修改 REBORN。保留此前所有本地开发成果，不改 NEXT、原版、武器数值、怪物数量、画质档位或存档键。原始记录位于工作区 `outputs/reborn-coast-stability-v227/`，安装包与打包核对位于 `outputs/reborn-install-v227/`。

## 海港的实际变化

- 从桥口的真实探索视线寻找干燥远岸，在现有地面上形成最多两处宽缓岸肩。它们是可行走、具有相同高度采样和碰撞约束的岸地，受到最高潮位、桥、道路、奖励和固定景物的保护。
- 原先每个小货袋、网卷或小桶也会压平周围一片地面。现在仅让独立、半径不超过 0.4 米的四类非交互海港装饰随坡落地，同步模型底部与碰撞底高。船、桥、建筑、奖励、可破坏物和战术物件保留原标高与规则。
- 现有远景外环按同一桥口视线形成不同宽高的岬角轮廓，保留近圈码头承托和出海水口。远景在游玩边界外，实际可达的岸坡由地面单独实现，不将无碰撞背景山冒充近景可达区域。
- 合流地图的海港区域同步生效，继续通过原生物群系权重过渡；原森林及其他地区的保护保持。

没有增加地面顶点、场景网格数、灯光、纹理或逐帧地形计算；随坡贴合的装饰面可能增加少量三角形。几何与材质继续复用原系统。没有本轮新增外部素材或新的授权依赖。

## 对上一轮停顿判断的修正

v226 的短时性能夹具通过 `start(true)` 直接进入战斗，绕过了正式开始按钮调用的战斗资源准备。CPU 采样将游戏第 12 秒怪物出现时的一次诊断长帧，定位到 Three.js `WebGLProgram.onFirstUse → getUniforms → getProgramInfoLog` 的着色器首次使用同步等待。带采样器的约 157ms 耗时不能与上一轮不带采样器的约 112ms 直接比较。

同一冻结版本、相同种子改为正式准备流程后，该峰值没有复现。随后通过正常开始按钮完成准备，再巡检五个区域并调用现有生成入口加入对应怪物；基线桌面和手机尺寸各 60 秒，最大 RAF 间隔分别为 22.3ms、23.6ms。巡检在测试夹具中移动到区域观测点，不代表自然步行或一小时实战。

因此没有为了错误夹具增加第二套预热、减少怪物或降低画质。后续真机测试又发现了一处独立、实际存在的遗漏，修复如下。不能用基线结果代替新版验证，也不能把原生 RAF 间隔称为显示器实际呈现 FPS。

## 真机定位到的阴影首用停顿

红米 K80 Pro 的 Chrome 正式准备后，在切入海港并同帧生成三种海怪时，冻结基线和修复前候选分别出现约 96.6ms、77.8ms 的 RAF 间隔；该帧游戏回调约 93.1ms、75.3ms。两次设备温度、驱动缓存不同，差额不能算作性能提升。测试夹具中的瞬移放大了同帧压力，但正常海港营地确实也会同帧生成海龟、水母、潮蟹，不能据此忽略风险。

短时 CPU 和新增着色器采样将主要等待定位到实例化桥板和环境组合的两个阴影程序：普通反面深度程序，以及带实例颜色的双面深度程序。原加载绘制只纳入扫描模型的实例批次，入口阴影视野以外的桥和组合物没有实际绘制这些变体。海怪本身的关节/网格构建不是这次主要阻塞来源；夹具存档为隔离的内存存储，此次也不是用户存档写盘造成。

`withSceneryBatchSamples` 现在在原有准备绘制中同时纳入场景内实际投射阴影的实例批次，每批只临时绘制一个已有实例。保留原实例矩阵、颜色、材质、图层、阴影质量及资源所有权；数量、可见性与剔除开关通过 `finally` 恢复，失败也不会改变正常场景。未新增逐帧工作、第二套加载流程或新的性能降级策略。代价是将原本游玩中才发生的少量准备工作提前到加载阶段，不宣称首次完整加载因此缩短。

- `npm test`：本轮重新运行，1474 项通过、0 失败、1 项既有条件跳过，约 66.8 秒。含新增岸坡、保护区、碰撞底高和实例阴影变体测试。跳过项没有算作通过。
- 最终桌面和桌面模拟手机尺寸各 60 秒：正式开始后巡过五区并各生成三只真实区域敌人；最大 RAF 间隔分别 23.0ms、41.4ms，均没有超过 50ms。模拟手机尺寸不等于手机硬件测试，也不能将这些间隔等同于显示器实际呈现帧率。
- 红米 K80 Pro / Chrome 151 真机 60 秒：固定 844×390 渲染、移动档、画质系数保持 1。修复前后同一海港切区及三怪生成回调约 75.3→29.0ms；最终窗口 1800 次渲染提交，约每秒 30 次。最大游戏回调 47.4ms，最大 RAF 间隔 50.2ms；仍有 33–50ms 波动，不称完全无卡顿。该测试使用独立内存存档、静音和固定巡检点，不能代替长时间正常实战，也不是系统 WebView 中的 APK 安装测试。
- 还发现 `SM_Cluster_coast_0_0` 的一个双面深度程序首次使用约 9.8ms。现有 Three.js 共用深度材质的状态切换仍有此边界；本轮没有修改引擎或强加额外完整场景绘制。正式加载时间没有通过冷缓存多轮对照证实缩短。
- 真机帧外 `canvas.toDataURL` 得到的黑色 PNG 不作为视觉验收图片。实际同机位环境截图使用桌面游戏的即时绘制捕获；两类证据明确区分。

真机修复前测量时温度约 37.5°C，最终约 35.7–36.1°C，驱动缓存状态也不同；不能把两次总耗时差额全部归因于补丁。首次阴影程序的采样栈和具体变体覆盖是本次修复的独立证据。

海港在四个冻结机位、两种视角分别保留桌面前后截图和手机尺寸截图；新岸坡另存坡脚/坡顶对比。坡脚至坡顶实际调用原移动入口，连续行走 24.458 米、272 步，地面支撑误差 0。入口视觉变化较小，桥口的远岸轮廓和可达坡地有所改善，不宣称整张地图已经质变。截图与对比表保存在 `before/`、`after/`、`shore/`、`comparison/`。

计时原始数据为 `profiles/*formal-tour-plain*.json`，着色器归因为 `profiles/*shader-profile.json`，完整汇总为 `QA-REPORT.md` 和 `qa-performance-final.json`，均在上述工作区输出目录。CPU 回调、渲染提交次数、原生 RAF 间隔和 GPU 计时含义不同；不把它们混成一个 FPS 指标。

## 安装包入口

- 安卓：`Realm-Echoes-REBORN-v227.1-Android.apk`，包名和签名沿用 v225，安装后打开「异境回响 REBORN」。同包名旧版可覆盖安装，不要先卸载或清数据。
- Windows 10/11：完整解压 `异境回响-REBORN-v227-电脑离线包.zip`，双击根目录「启动异境回响.exe」。小型启动器使用系统自带 .NET Framework，只在 `127.0.0.1:8897` 提供本地游戏资源，无需额外安装 Python 或 Node.js。使用已装 Edge/Chrome 的独立应用窗口，默认全屏、无地址栏；不用 kiosk 或隐私模式，不另建生产用户资料。端口占用时明确报错，不杀其他服务或更换存档来源。
- `Esc` 为游戏暂停，`F11` 切换全屏/窗口，`Alt+Tab` 切换应用，`Alt+F4` 关闭游戏窗口。启动器只关联本次新开的游戏窗口，关闭后结束本地服务；不结束浏览器共享进程，也不向此前普通浏览器窗口发送全屏按键。继续选择之前玩电脑版的同一浏览器/用户资料，其他资料的存档不会自动迁移。
- 电脑 ZIP 是便携离线包，不是带安装向导的 Setup。安卓仍使用系统 WebView、电脑仍使用浏览器渲染；包装不会消除 GPU、发热和操作系统调度的成本。
- 网页、电脑本地来源及安卓存档分别保存，不会自动互通。包内包含完整游戏资源，不包含用户浏览器存档。

两个包均逐文件核对最终离线清单，Android 继续使用 v225 的签名和固定本地来源，未在手机上安装或清除应用。Windows 包内 EXE 的实际 HTTP 资源服务、MIME、长连接、Range、白名单、退出与端口释放通过构建检查。可见全屏窗口已实际打开，用户确认效果成功并要求停止再次打开；因此停止自动化窗口重试，未把中断的全屏/按键/存档持久化脚本记为全部通过。后续未再打开测试游戏。自动化的长期游玩、系统 WebView 性能和完整的窗口生命周期仍需人工试玩；本轮游戏功能回归以此前桌面实际游戏检查和上述测试记录为准。
