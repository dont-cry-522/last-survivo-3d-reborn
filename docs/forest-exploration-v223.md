本轮以本地 v222 完整工作快照为基线，只修改 REBORN；未回退、提交或推送 NEXT 与原版。增量基线位于工作区 `outputs/reborn-forest-v223/baseline/`，不以旧 Git HEAD 代表修改前状态。

## 森林的实际变化

坡面沿用 v222 的入口斜脊、溪岸高地和溪源台地，在既有轮廓中加入不对称的坡肩、缓台与两条宽窄不同、向溪侧弯出的浅沟。浅沟在坡体组合之后扣除，避免被相邻山坡填平。不是增加均匀的随机噪声，也没有增加地形细分。

地面仍为 144×144 网格、41,472 个三角形；路径、水岸、奖励、实体位置及通行规则保持原有保护。五种子检查的合成坡度上限仍约 0.311，脚底与绘制地表共用同一高度采样。固定种子 522 的最高点由 5.288m 变为 5.066m，主要变化是拆开圆滑坡面，而非把整座山抬高。

原来的林缘植被优先围绕离出生点最近的几棵树布置，有限配额很早耗尽。现在将相同配额分散到沿路景观节点；水岸节点优先连接实际视线中的远岸树群。低矮地被与中层蕨灌木沿同一组林缘形成两处不对称的植被簇，中间保留留白，继续避让道路、障碍、奖励和水体。

这是重分配已有实例；没有新贴图、新材质、新植被模型或新的逐帧循环。森林旅程允许最多重分配各层的 30%，其他地图保留原来的规则。按种类和分区实例化批次保持，随机种子可复现，仍按实际地形贴地。固定种子 522 的低层仍为 1200 实例 / 2 批次 / 96,092 三角，中层仍为 1127 实例 / 11 批次 / 142,704 三角；沿路实际重布低层 235 个、中层 215 个。

## 人物切换

正式入口的修改前测试复现了首次选择其他人物和首次查看近景的加载遮罩。后续切换已有缓存很快，但之前只在进入大厅时准备当前人物，其他人物的模型构建与光影准备推迟到了点击时。

本轮将七位英雄的默认装备预览准备集中到进入大厅阶段，并复用已准备的人物。备用武器继续按需准备，避免一开始生成所有装备组合。全身与近景现在使用相同的四个侧裁剪平面，平面位置和镜头取景只是参数变化，不再各自编译一套着色器。全身原有 14% 取景余量保留；伙伴也使用同样平面，所有临时裁剪在绘制结束后还原，战斗不受影响。高画质与直接渲染两种输出仍分别预热，未降低人物材质或游戏光照。

预热期间只排除已准备的环境网格绘制，真实灯光、雾和环境反射仍保留；恢复时同时还原环境层、人物父级、位置、显隐、镜头与渲染目标。模型、几何和材质缓存保留在当前页面，关闭页面后 GPU 准备仍需要重做。

初稿分别预热两种取景，大厅等待约 33 秒；合批编译的试验反而约 37 秒，且有首帧波动，已弃用。共用预览程序后先降至约 25 秒，但仍发现环境零裁剪与人物四裁剪的准备不一致，导致首次真实场景绘制重复编译。最终将场景与人物按各自实际变体准备，桌面首次大厅实测 18.619 秒，同浏览器正常刷新 17.050 秒；仍高于旧版仅准备一个人物的同轮基线 13.681 秒。初始最大长任务由候选版的 4.064 秒降至 671ms，仍不是无卡顿启动。

桌面真实连续点击七人全身、重复全身、七人近景共 21 次：无加载遮罩、无新增程序编译，首次人物画布提交为 10–21.9ms，之后 500ms 观察窗口没有超过 50ms 的长任务。这是本机观察结果，不是所有设备的保证；画布提交时间也不是屏幕真正显示时刻。关闭页面后仍需要重新准备 GPU 资源，其他备用武器首次选择仍按需加载。完整加载、首帧和连续运行检查见本轮验证记录。

手机尺寸/触控模拟的另 21 次切换同样没有遮罩或新增程序，画布提交 14.2–38ms；首次大厅 18.305 秒、刷新 16.841 秒。提前保留七人也有内存成本：同一早期场景的 GPU 资源对象由 374 几何 / 122 纹理增至 553 / 224，不等于这些对象消耗多少字节，不应称为零成本优化。

连续路线测试又复现了首次经过溪弯时 411–644ms 的同步编译停顿。程序键确认：预览残留的四裁剪平面被用于战斗预编译，未被起始视野覆盖的场景物件后来才补编译零平面版本。最终新增 `compileWorldAsync`，每个战斗准备 pass 用复用空场景归一化裁剪状态，再按真实场景灯光编译。它不清屏、不更改场景内容或材质，异常也恢复绘制策略。最终路线复测记录与修改前失败记录分别保留，选人/森林外观结果则沿用相关逻辑不变的候选版本，详见 QA 报告。

最终手机尺寸同路径的 30 秒定向复测不再补编译那四个错误程序：约 29.97 次渲染提交/秒，CPU 提交中位 3.2ms / P95 5.6ms / 最大 24.6ms；提交间隔 P95 34.2ms / 最大 36.1ms，无超过 50ms 的间隔。该次含诊断探针，只用于确认问题消失，不冒充与无探针基线严格等价的性能对比。切到第三人称仍首次创建 11 个深度程序，该帧 24.6ms；尚未实现所有场景绝无新增程序或绝无卡顿。

最终森林外观候选在无探针桌面独立采样中，约 59.98 次提交/秒、CPU 中位 3.1ms / P95 5.9ms；同轮冻结基线为 59.93 次/秒、3.1ms / 5.7ms。这些数字是当前电脑的渲染提交观察，不是 GPU 帧耗时或真机手机 FPS。纯粹缓存更多人物会增加驻留资源，后续最值得改善的是首次启动准备成本与人物共享资源，而非继续堆高植被数量。
