## 实际实现

- 大厅首次只准备当前英雄和装备，不再先准备全部 17 种组合。未使用的装备第一次选择时显示准备层，完成后缓存模型及渲染程序；近景肖像仍按需准备。失败保持锁定并允许重试。
- 人物下载保持并行，模型逐个解析、衣物与表面处理按阶段让出主线程；压缩加载、glTF/bin 回退和失败资源回收均保留。并发调用共用同一准备任务，全部完成后再开放模型使用。
- 战斗前继续预热敌人、武器、音频、材质与第一/第三人称，避免将开销推迟到第一次攻击。
- 实际执行现有画质档位的 60 / 30 Hz 目标。高刷新浏览器不再每次回调都进行更新和渲染。显示回调、模拟步骤、渲染提交分别统计。
- 暂停、准备、隐藏恢复时重置时钟；较长正常帧分为最多 3 个、不超过 40ms 的模拟步骤，总时间保护上限 120ms。升级或死亡发生后不继续后续模拟步骤。
- 修正原有射击计时丢失帧余量的问题，保持不同更新频率下的攻击频率；停火、无目标、闪避期间不积攒连射。装填动画时长和伤害未改。
- 扑击最后一步只移动实际剩余时间，避免低帧率下狼与蘑菇额外冲出。
- 地形/地表纹理/水岸/树木候选/地被/五境构建按小段执行；主加载流程按约 7ms CPU 预算让出浏览器。原同步构建接口保留。
- 40m 内整冠动画保持逐帧，40–80m 为 15Hz、80m 外为 8Hz；GPU 叶片风仍逐帧，回到近处立即恢复。未削减场景物件、碰撞、奖励和战斗内容。

## 验证方法与边界

同设备 Edge 155、RTX 3080 Ti / D3D11，桌面 1440×900 均衡、手机尺寸 844×390 移动档。每轮独立上下文，60 秒实际墙钟移动攻击，固定 seed 522。手机尺寸模拟不代表安卓真机。

渲染 CPU 提交时间不等于 GPU 帧时间，执行渲染频率不等于屏幕呈现 FPS。离线与 APK 只消除外网资源依赖，不能保证所有硬件零卡顿。加载层中的准备耗时与游玩时的停顿分开记录。
