# v220 · 首次使用停顿与运行时重复工作

本轮在 REBORN 本地 v219 的未提交工作上增量修改，保留森林地形、树种、角色、敌人、碰撞、伤害、画质档位和存档。没有修改 NEXT，也没有提交、推送或发布。没有新增模型、贴图、依赖或运行时外网请求。

## 实际修改

- `audio.js`：入场准备当前武器的原有声音变体，优先复用录制声音；需要合成的回退声音分段缓存。准备过程不播放声音，不改变音色、随机取样或攻击冷却。
- `tree-scenery.js`、`render-prewarm.js`：提前生成实际地图会用到的树冠近、中、远档，并在加载层后用共享资源完成首次上传。扫描景物的既有细节层级也参加准备；不降低阈值或删减植被。
- `combat-prewarm.js`：准备当前弹道及两条成长路线、普通混合碎片/线条、危险地面提示。保留一个有界的预警样本，清理时不销毁仍会复用的资源。不会触发战斗、生成奖励或推进时间。
- `main.js`：完整准备第一/第三人称与两种渲染路径；第一人称编译只遍历手臂和武器，使用实际场景灯光，避免重复编译整张地图。正式界面的返回大厅分段重建并显示准备进度，失败可重试。
- `hero-preview.js`、`main.js`：人物近景按需异步编译并缓存。当前 Three.js 的编译方法不自行更新局部裁剪计数，因此先通过空场景及公开裁剪接口建立对应状态，再只编译当前人物，随后真实绘制。所有临时灯光、裁剪、相机与渲染目标恢复原状；未修改 Three.js 内部实现。没有把 17 套近景全部塞进首次启动。
- `environment-assets.js`：细节档位切换时，只更新发生变化的实例批次。
- `confluence.js`、`world.js`：复用生物群系权重输出，去除天气粒子重复创建的临时数组；权重数值、粒子数量和随机序列保持不变。
- 对应自动化测试及 `tests/smoothness-check.html`：覆盖缓存、失败清理、正常返回/重开、不同视角和真实浏览器回调。版本与离线清单同步为 v220。
