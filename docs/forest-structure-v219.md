# v219 · 森林地势与树群结构

本轮在 REBORN 开发副本中继续建设独立森林示范地图。重点从表面细节转向真实地势和树林结构：让已有溪岸路线经过缓坡、林荫、转弯与开阔处，同时保留原有战斗、奖励和交互位置。没有把此项改动套用到另外四张地图或五境合图，也没有新增地图、任务、角色或武器。

本地试玩入口：[当前开发版本](http://127.0.0.1:18919/current/play.html?v=219)。需要本轮本地服务器运行；选择森林后，可分别使用第一、第三人称观察沿溪路线。`v=219` 是本轮版本标识，不代表 Git 提交或线上发布已经完成。

## 宏观地形

`forest-macro-landform.js` 根据已有 `world.forestJourney.points` 的方向、长度和水域位置选取宽缓地势，而非在地图上铺均匀噪声。地势与旧地表在 `forest-terrain.js` 中合成为同一个地面网格。

| 结构 | 当前源代码参数 | 作用 |
| --- | --- | --- |
| 溪谷侧坡 | 路线约 32% 附近；半径 32×25m；设计高度 3.8m | 从低水岸向陆地抬升，提供有体积的中景 |
| 后段高地 | 路线约 78% 附近；半径 27×21m；设计高度 3.0m | 形成不同高度的后段林地与远景遮挡 |
| 穿路鞍部 | 从距起点 12m 至终点前 9m，按 2m 步长挑选干燥区；半径 20×12m；设计高度 1.55m | 让实际步行路线有上坡和下坡，而不是永远停留在两侧山坡间的零高度沟槽 |

侧坡候选点沿路径法线偏移 12/20/28m，沿切线偏移 -7/0/7m；避开出生点、边界、保护区域和另一处已选高地。不同地势取较高值而不相加。设计高度会被水岸、建筑等保护范围和坡度约束压低，不能作为实际可见峰值宣传。

独立森林继续使用 144×144 格地面，合计 41,472 个三角形；没有新增一层山丘网格。高度非负，地图边界前 16m 至前 5m 平滑收低。X/Z 方向每米的高差分别不超过 0.22，三角面合成坡度上界约 0.311。旧地图和未启用示范路线的地形仍采用原来的 0.12 单轴限制。

在地形限定夹具中，实际安装后的结果如下。它们来自地面顶点和沿路采样，不是渲染帧率或画面质量评定。

| 地图种子 | 地面实际最高点 | 每 2m 采样的路线峰值 | 最大三角面坡度 |
| --- | --- | --- | --- |
| 7 | 3.561m | 0.943m | 0.311 |
| 522 | 3.618m | 0.750m | 0.311 |
| 43837033 | 3.301m | 0.957m | 0.311 |

种子 522 的路线后半段先由零高度爬升到约 0.60m，回落到约 0.21m，再经过约 0.75m 的坡段，下降到接近末端的约 0.32m；实际水岸保护区仍为零高度。随机布局不同，坡的位置和最终高度也不同。

## 地面、树根与碰撞一致性

渲染网格和 `world.groundHeightAt` 使用同一组顶点及同一种三角插值。人物、伙伴、地面敌人、跳跃落地、相机和弹道继续调用既有支撑及碰撞系统，没有引入另一套近似地面或改变移动速度。

允许随坡面抬升的对象仅为普通、永久、非交互森林树。它们仍位于原来的 XZ 坐标，碰撞半径不变。可破坏树、战术障碍、遗迹、建筑、重要古树和交互地标不使用该规则。水域及最高岸线包络、桥、浅滩通道、出生地、奖励与交互区域保持原来地面基准。

树的最低根环在当前真实坡面上逐点取保守落位，预留约 0.015m 埋入量，避免下坡一侧浮空。树抬升后，碰撞底部写入 `obstacle.y`，`height` 保持局部高度；`world.js` 的移动及支撑顶面使用 `y + height`，与相机及弹道已有约定一致。不能在抬升后再次把世界空间包围盒最高点当作局部高度。

草、蕨叶及已有细节实例在构建阶段按同一采样器挂地；它们的 XZ、旋转、共享几何和材质保留。原有自有地面贴片按需细分、贴合高差，总新增三角预算仍限制为 8,192，不新增绘制网格。`forest-floor-relief.js` 的树根土肩同样采样当地坡面，边缘埋入地面，且全部留在既有树木碰撞范围内。

## 四种结构树形与远景树林

`forest-tree-forms.js` 为路线附近的已有树替换树干、分枝与冠层结构。四族各有两种变体，共预构建八套共享模板；并非把同一树冠换颜色或只做横向缩放。

| 树形族 | 结构特征 | 沿路线的主要分段 |
| --- | --- | --- |
| `oak` 分叉橡树 | 不等长主枝、较低侧枝、宽而互相交叠的冠肩 | 前 24% |
| `wind` 风塑树 | 弯曲主干，枝叶偏向一侧，背风侧保留稀疏旧枝 | 24%–49% |
| `alder` 溪岸桤木 | S 形细长主干、交替向上分枝、较小且错落的叶簇 | 49%–69% |
| `highcanopy` 高冠谷林树 | 高净空主干和抬升冠层，保留看向溪岸的视线 | 后 31% |

默认在距路线 24m 内选择至多 36 株，且不超过合格普通树数量的三分之二。分段轮流取样，避免入口密集树群耗尽预算。替换保留原树对象、材质、根部变换、碰撞对象与风摆记录；低叶片为既有风摆留出至少约 3.55m 的静态净空。最终根部高度由后续地形挂地决定。

树干和枝条采用独立沿长度展开的 UV，周向接缝共享光滑法线。叶片沿真实枝梢定位，使用弯曲叶簇与少量近处折叶，复用现有叶图集和透光/风摆材质。三级冠层 LOD 使用同一组枝梢锚点；近处增加细节，远处不会突然换成另一种轮廓。沿用 `tree-scenery.js` 的距离迟滞：近档进入约 9m、退出约 11m，远档进入约 32m、退出约 28m。

外围林线继续使用原有 240 个树位和六个实例批次，即三个树干批次、三个树冠批次，每批 80 个实例。批次分别使用橡树、风塑树和高冠树的轻量结构，按原有林带聚类分配；远景没有增加碰撞体或逐帧更新，也没有把 240 棵树变成 240 次独立绘制。八套模板是应用级共享缓存，场景只释放自身拥有的替代几何及实例缓冲，不能随单棵树释放共享模板。

## 构建顺序与文件

实际接入顺序为：既有地图和生态 → 原探索路线 → `planForestJourney` → 原地标与构图 → `finishForestJourney` → `installForestTreeForms` → 原障碍高度测量 → 原林间光柱/雾与远景 → `installForestTreeBackdropVariants` → 地表细节 → `installForestTerrain` → 接地遮罩 → `installForestFloorRelief` → 提示物贴地与最终场景接入。

主要涉及：

- `forest-macro-landform.js`：溪谷侧坡、高地与路线鞍部的布置参数。
- `forest-terrain.js`：实际高度网格、采样、坡度、挂地和贴片处理。
- `forest-floor-relief.js`：树根土肩接缝。
- `forest-tree-forms.js`：四族树形、八模板、LOD 和既有远景批次替换。
- `main.js`：按既有场景加载顺序接入。
- `world.js`：抬升障碍的世界空间顶面统一。
- `tests/forest-macro-terrain.test.js`、`tests/forest-tree-forms.test.js`、`tests/forest-structure-integration.test.js`、`tests/adventure-terrain.test.js` 及原地形/路线测试：对应结构、支撑、旧规则和资源生命周期检查。

新树形必须在地形前安装，避免地形使用旧树根环落位；地形之后不得再把树根 Y 重置为零。需要在完整组合和实际浏览器中检查第一人称树冠净空、第三人称相机避障、坡脚根部、水岸接缝和沿路遮挡。代码检查不能代替观感、触屏或真机性能判断。

独立组合检查按真实接入顺序运行：种子 7 和 522 分别有 22 和 20 株新结构树处于宏观坡面上；最低根环最高点相对采样地面的间隙为 -0.015m，碰撞顶面与模型世界包围盒一致。组合检查还覆盖道路行走、双视角、地形抬升后的光柱/薄雾位置更新、弹道和自有资源释放。该检查不依赖浏览器画面，因此仍需与实景记录一起判断。
